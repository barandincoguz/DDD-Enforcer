### WP-CORE-31b (commit `64043ca`) — import-topology pipeline integration
- New module-level helper
  `core/AST/import_graph.py:apply_import_topology_to_model(model_data,
  python_files, workspace_root=None)`.
- Composes the WP-CORE-31 trio (`build_module_import_graph`,
  `map_modules_to_contexts`, `derive_context_dependencies`) into a
  single mutation:
  - Auto-populates `BoundedContext.allowed_dependencies` when LLM left
    it `None`/`[]` AND derived graph found cross-context edges.
  - Preserves existing non-empty LLM-declared `allowed_dependencies`;
    records sym-diff under `cross_check_diff[<ctx>]` with
    `extra_in_llm` and `extra_in_derived`.
  - Intra-context imports excluded (re-verified by regression test).
  - Unmapped contexts skipped (no false `[]` confidence).
- Returns JSON-safe diagnostics: `{derived, auto_populated,
  cross_check_diff}`.
- `core/AST/ast_model_signals.py:_apply_import_topology` (new method)
  calls the helper after `enricher.enrich_model(...)` and stashes the
  diagnostics on `enricher.diagnostics["import_topology"]` so they
  end up in `ast_signals_diagnostics.json` next to the other AST counts.
- `SignalEnricher.enrich_model` is NOT touched.  Post-enrich step only
  mutates `model_data["bounded_contexts"][i]["allowed_dependencies"]`,
  nothing else.
- `tests/test_import_topology_integration.py`: 10 tests.

### WP-CORE-20b (commit `9f4ad0c`) — wrap architect-pipeline stages
- New module-level helper
  `core/orchestration/pipeline.py:_optional_stage(name)` context manager.
  Composes `StageEmitter.stage(name)` when an emitter is on the
  ContextVar; otherwise yields no-op (existing emitter-less call sites
  keep working unchanged).
- `run_pipeline` now wraps the four stage dispatch points:
  - `deps.scout(srs_text)` -> `with _optional_stage("scout")`
  - `deps.architect(scout)` / `deps.architect_with_feedback(...)`
    -> `with _optional_stage("architect")` (BOTH the initial attempt
    and the WP-CORE-7 feedback rerun execute inside the architect
    scope so rerun-time LLM records land in the architect bucket too).
  - `deps.specialist(arch, scout)` (both initial call AND the
    refiner's `_re_run_specialist` stage_runner) ->
    `with _optional_stage("specialist")`.
  - `deps.synthesizer(refined_specialist)` ->
    `with _optional_stage("synthesizer")` (post-call empty-model guard
    stays OUTSIDE the wrap so SynthesizerEmptyModelError still raises).
- StageEmitter is NOT modified.
- Documented follow-up (WP-CORE-20c): architect rerun re-enters the
  "architect" scope and overwrites the prior `StageRecord` —
  rerun-attempt-1 `llm_calls` records are lost across the overwrite.
  Paper-data integrity is dominated by the final successful attempt,
  but a proper preserve-rerun mode is a separate WP.
- `tests/test_pipeline_stage_wrapping.py`: 8 tests.

### WP-CORE-29b (commit `8db7997`) — rag _parse_sections period regex
- `core/rag_pipeline.py:_parse_sections` regex tightened from
  `^(\d+(?:\.\d+)*)\s+(.+)$` to `^(\d+(?:\.\d+)*)\.?\s+(.+)$`.
- Now matches both `1 Title` and `1. Title` forms (the period+space
  form is the more common SRS style; previously it fell through into
  the Preamble fallback section, defeating section-aware RAG chunking).
- Mirrors `document_parser.heading_pattern`'s pre-existing optional
  `\.?` form.
- `tests/test_rag_pipeline_core.py`: 3 new tests appended to
  `TestParseSections` (T-RAG-PARSE-5, T-RAG-PARSE-6, T-RAG-PARSE-7).

### WP-CORE-27a (commit `effd5df`) — VO is_mutable_in_code population
- New pure helper `core/AST/mutability_index.py:build_mutability_index(
  python_files) -> Dict[str, bool]`.  Walks every Python class in the
  workspace and returns `{class_name_lower: is_mutable}` where
  `is_mutable = bool(facts.mutation_methods)`.
- Same-name conflict resolution: `True` wins (D9 risk model is
  asymmetric).  Parse failures silently skipped.
- `SignalEnricher.enrich_model` gains keyword-only param
  `mutability_index: Optional[Dict[str, bool]] = None`.  After the main
  merge + traceability pass, each LLM-claimed VO whose name appears in
  the index is stamped with `is_mutable_in_code = index[name.lower()]`.
- `ASTModelSignalExtractor.enrich_domain_model` builds the index from
  the workspace's Python files and threads it through.
- D9 (`check_d9_value_object_mutability_consistency`, shipped in
  WP-CORE-27) was vacuously satisfied before this WP — every claimed
  VO carried the default False.  Now the check is real.
- `tests/test_vo_mutability_index.py`: 8 tests.
